# 2026-10-13

- 시연·데모용 합성 데이터는 실제 도메인 제약(활성 훈련자, 실행 가능한 훈련 등)을 그대로 통과하는 레코드만으로 만들어야 한다. 제약을 우회한 가짜 데이터는 리포트·집계 로직에서 깨지거나 실데이터와 다른 분포를 만든다. 합성 데이터 생성은 스케줄러로 매일 돌려 리포트가 항상 채워진 상태를 유지한다.
- 저장 레코드에 "작성자 이름" 같은 표시용 정보를 넣을 때 JWT principal 의 클레임을 그대로 쓰면 토큰 발급 시점 값이라 변경 사항이 반영되지 않는다. 표시용 사용자 정보는 principal 의 ID 로 사용자 테이블을 조회해 현재 값을 읽는다.
- 수동 발행 문서의 "최종본"은 덮어쓰지 말고 (대상 기관, 청구월) 키 기준으로 버전을 올려 append 저장한다. 이력 조회 API 를 함께 두면 감사·롤백이 쉽고, 최신본은 버전 최댓값으로 가져온다.
- 파트너/프로모션 코드 유형별로 승인 흐름을 분기할 때, 체험형 코드는 등록 즉시 자동 승인 + 고정 기간(14일) 플랜 부여로 단축한다. 승인 상태·플랜 부여를 코드 등록 트랜잭션 안에서 처리해 중간 상태가 남지 않게 한다.
- 데이터가 여러 경로(일괄등록, 시드, 수동)로 들어오는 엔티티에는 "연동 경로(source)" 컬럼을 두어 출처를 추적한다. 컬럼을 나중에 추가하면 기존 행은 null 이므로, 추가와 동시에 기존 행을 백필하는 마이그레이션을 같이 넣는다.
