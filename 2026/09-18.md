# 2026-09-18

- 동일한 "최고 기록" 선정 로직이 목록 조회와 상세 조회에 각각 흩어져 있으면 정렬 기준·타이브레이커가 미묘하게 어긋나 조회 경로에 따라 결과가 달라진다. 선정 규칙을 한 곳으로 모으고 QueryDSL 쿼리와 애플리케이션 계층 양쪽이 같은 기준을 쓰도록 통일.
- 분석 리포트에 표준 분류 코드(ICF 등)와 난이도 구간별 최고 기록을 함께 싣는 구조. 원시 기록 테이블을 난이도로 그룹핑해 그룹별 대표값을 뽑는 집계는 JPA 기본 쿼리보다 QueryDSL 서브쿼리/윈도우 조합이 깔끔하다.
- 세션 종료를 "사용자가 명시적으로 끝냄"과 "유휴 타임아웃 자동 종료"로 구분해 사유 enum으로 저장. 둘을 한 상태로 뭉개면 이탈률·완주율 지표가 실제보다 왜곡된다. 종료 경로별로 기록 시점을 명확히 잡는 게 핵심.
- 내부 QA 페이지에서 폼 submit 이나 동기 요청으로 API 를 호출하면 액세스 토큰 만료 시 401 응답이 그대로 화면에 노출된다. `fetch` 기반 호출로 바꿔 응답 상태를 직접 받고 재발급/재시도 흐름을 태울 수 있게 처리.
- QA 시나리오는 실제 사용 흐름(훈련 진행 → 종료)을 그대로 밟아야 한다. 상태 전이를 건너뛰고 종료만 호출하면 통과해도 실제 버그를 못 잡는다.
- 검증이 끝난 일회성 QA 페이지는 쌓아두지 말고 정리. 남겨두면 인증·권한 우회 경로로 남고 유지보수 비용만 늘어난다.
- AI 프록시 계층에서 벤더 오류를 성격별로 분류(재시도 가능한 일시 오류 / 쿼터·레이트리밋 / 모델 소멸·미지원 / 요청 자체 오류)하고, 모델 소멸(deprecated·삭제) 계열은 대체 모델로 자동 폴백. 오류를 단일 예외로 뭉개면 재시도해봐야 소용없는 상황에서 계속 재시도하게 된다.
- 모델 ID 를 코드에 하드코딩하면 벤더가 모델을 내릴 때마다 배포가 필요하다. 서버 측 별칭(논리 이름 → 실제 모델 ID 매핑)을 두고 설정만 바꿔 교체할 수 있게 하는 편이 안전하다.
